# 추가 오류 수정과 검증 — 2026-10-04

긴 용어집과 잘못된 모델 응답, 분석 중 편집을 중심으로 추가 점검했다. 기존 소설 프로젝트의 문서와 완료 상태는 유지했다.

## 재현하고 수정한 문제

1. **원문에 없는 기준 이름 저장:** `Mira`라는 실제 별칭만 근거에 있으면 `Princess Mirabelle`처럼 원문에 없는 기준 원어도 저장할 수 있었다. 용어집 생성과 번역에서 기준 원어 자체가 현재 원문에 있는지 추가 검사한다. 잘못된 응답은 기존의 최대 두 번 수정 요청을 거쳐 처리한다.
2. **긴 메모가 문맥을 차지함:** 관계없는 용어 메모까지 전달해 용어집 생성이 60,000자 제한에서 실패하거나 모델 문맥을 넘길 수 있었다. 전달 사본만 UTF-8 20,000바이트로 제한하고 이번 원문에 필요한 용어와 전체 메모를 우선한다. 다른 용어는 기준 이름·번역부터 전달하고 남는 공간에 메모를 넣는다. 필요한 항목만으로 초과하면 오류로 중단하며 원본 용어집은 변경하지 않는다.
3. **불완전한 모델 응답 수락:** Ollama의 `done: true`만 확인해 `done_reason: length`도 정상 응답으로 받을 수 있었다. 출력 한도 응답을 거절하고 원문·용어집을 잘라 처리하는 `truncate`와 생성 중 문맥을 밀어내는 `shift`를 비활성화했다. 실제 문맥 초과는 재개 방법을 포함한 한국어 오류로 표시한다.
4. **분석 중 변경된 기준에 이전 결과 저장:** 프로젝트 용어집 생성은 분석 도중 용어집 변경을 확인하지 않았다. 요청 때의 기준과 저장 직전 기준을 비교해 변경되면 해당 묶음의 저장을 거절한다. 사용자가 편집한 기준은 유지하고 묶음 완료 수를 늘리지 않는다.
5. **재검증에 구체적인 규칙 결과 없음:** 실제 모델의 중간 실행에서 규칙 이슈가 남는 경우를 확인했다. 초벌 번역에서 발견한 숫자·변수·용어 검사 결과를 재검증 모델에 함께 전달한다. 정당한 단위 변환 등을 경고에 맞춰 왜곡하지 않도록 지시하며, 남은 이슈는 계속 화면에 표시한다.

강화된 기준 원어 검사로 다시 검증하도록 모델 용어집 처리 지문을 v3로 갱신했다. 이전 완료 문서나 저장된 용어는 삭제하지 않으며 다음 번역 시작 시 필요한 용어집 검증을 수행한다.

## Ollama 요청 근거

문맥 제한과 출력 종료 정보를 [공식 Chat API](https://docs.ollama.com/api/chat), [문맥 길이 안내](https://docs.ollama.com/context-length), 설치 버전과 같은 [v0.35.1 요청 타입](https://github.com/ollama/ollama/blob/v0.35.1/api/types.go)에서 확인했다. 요청 타입의 `truncate`와 `shift` 동작을 실제 로컬 API에서도 확인했다. 바이트 예산은 모델별 토큰 계산을 대신하지 않는다.
