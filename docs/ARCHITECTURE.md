# 구조와 데이터 불변 조건

## 실행 경계

`start.mjs`는 `127.0.0.1:4173`에 바인딩하는 로컬 Node 서버입니다. `frontend/dist`의 허용된 정적 형식과 React 라우트만 제공하며 소스 파일·환경 변수·임의 파일 경로를 제공하지 않습니다. GET/HEAD 정적 응답과 `/api/models`, `/api/model/test`, `/api/model`의 POST를 처리합니다. `local-model.mjs`는 요청을 검증하고 `127.0.0.1:11434` Ollama로 전달합니다. 모델 생성에는 temperature 0을 적용해 용어 선택과 구조화 응답의 무작위성을 줄입니다. 브라우저 연결이 종료되거나 사용자가 중지하면 상위 Ollama 요청의 `AbortSignal`도 취소합니다. 서버는 사용자 문서를 읽거나 저장하지 않습니다.

프런트엔드는 React + TypeScript입니다. `state/WorkspaceContext.tsx`가 IndexedDB 저장과 리비전 충돌을 관리하고, `state/AIJobsContext.tsx`가 페이지 밖에서 모델 작업·취소 컨트롤러·단계를 소유합니다. 따라서 화면 이동만으로 실행 중 요청을 중지하지 않습니다. 첫 구현은 브라우저별·다른 탭 사이에서도 로컬 모델 실행 하나를 기본으로 하며, `lib/runLease.ts`의 짧은 브라우저 lease로 다른 탭의 실행과 중단된 저장 상태를 구분합니다. 강제 종료 후에는 lease가 만료된 작업을 일시 중지로 복구합니다. 탭 종료 뒤 서버에서 계속 실행되는 기능은 제공하지 않습니다.

| 경로 | 역할 |
|---|---|
| `lib/model.ts`, `types/*` | 프로젝트·문서·용어·평가·작업 상태 타입과 상한 |
| `lib/projects.ts`, `lib/actions.ts` | 프로젝트 영구 등록, 문서 생성·편집·검수·평가 상태 전이 |
| `lib/projectGlossary.ts` | 작품 원문 묶음 생성, 지문별 완료 기록, 중단·재개·신규 원문 판정 |
| `lib/aiTranslation.ts` | 모델 기준 용어 자동 저장, 번역·재검증·구간 저장 |
| `lib/rules.ts`, `lib/terminology.ts` | 결정적 검사와 작품 기준 우선 적용 |
| `lib/validation.ts`, `lib/database.ts` | 저장·백업 검증, 리비전 충돌, 이전 백업 이관, 복구 사본 |
| `lib/uiState.ts` | 고정·최근 프로젝트, 최근 문서·문단, 접기, 모델 연결 확인 기록 |
| `lib/files.ts` | UTF-8 TXT/CSV/JSON 입출력, 자막 내보내기 |
| `components/layout/AppLayout.tsx` | 프로젝트 전환, 실제 작업 수치, 빠른 등록, 작업·모델 상태 |

## 저장과 범위

데이터베이스 `ian-review-workspace-v1`의 `workspace` store에 `current`와 선택적 `recovery`를 둡니다. Workspace `schemaVersion`은 1이고 `revision`은 저장마다 증가합니다. 모든 변경은 한 readwrite 트랜잭션에서 `현재 데이터 읽기 → expectedRevision 비교 → 복제본 변경 → 스키마 검사 → 쓰기` 순서로 처리합니다. 다른 탭이 먼저 저장하면 현재 입력을 덮어쓰지 않고 충돌을 알립니다. 복원 직전 데이터는 recovery에 보관합니다. 검증 실패 시 빈 데이터로 초기화하지 않습니다.

`projects`는 문서·용어·모델 설정과 독립된 프로젝트 목록입니다. 문서 등록도 이 목록을 채웁니다. 과거 백업에 목록이 없으면 연결된 자료의 프로젝트 이름을 읽어 명시적 목록으로 이관합니다. 프로젝트 이름 변경·삭제는 연결된 용어집 생성 상태도 함께 갱신합니다. 고정·최근·접기와 모델 연결 확인 기록은 `localStorage`의 UI 설정이며 문서 리비전이나 전체 JSON 백업에 포함되지 않습니다. 데이터 복원 후 존재하지 않는 프로젝트·문서 참조는 정리합니다.

용어집 생성은 처리한 원문 묶음의 지문을 저장합니다. 모델의 추출과 검증 응답을 모두 확인하고 **저장에 성공한 묶음만** 완료로 기록합니다. 수동 용어만 있으면 생성 완료로 판단하지 않습니다. 새 원고·수정 원고·모델 설정 변경으로 지문이 달라지면 해당 묶음을 다시 검증합니다. 모델이 검증한 용어는 바로 approved 상태로 저장하며 사람의 승인 대기를 만들지 않습니다. 기존 타깃은 고정하고 새로 관찰한 혼용 표기를 해당 프로젝트의 variants로 기록합니다. 공통 용어를 수정하지 않고 프로젝트 항목을 생성하므로 다른 작품에 영향이 없습니다. 과거 draft·pending 항목은 원문 문맥을 포함한 별도 모델 검증으로 결정하며, 누락·실패·중단 시 준비 완료로 표시하지 않습니다. 모델 용어집 파이프라인 지문을 갱신하여 이전 완료 기록도 새 절차에서 검증합니다.

번역·검증 요청은 glossaryDocument에 기준 용어, 별칭, 피할 표기, 맥락, 서술체 규칙을 포함합니다. 다른 회차의 같은 언어 쌍에서 확인된 번역도 짧은 문맥으로 전달합니다. 재검증에서 새 용어 타깃이 변경되면 초벌 표기를 교정한 결과를 저장합니다. 규칙 이슈가 없는 모델 재검증 구간은 자동으로 확인 완료됩니다.

번역 작업은 문서 `aiRun`에 대상 구간·저장 완료 수·모델·상태를 저장합니다. 완료 수에는 모델 응답만 받은 구간을 포함하지 않습니다. 원문·용어집·문단 리비전이 작업 중 바뀌면 오래된 결과 저장을 거절합니다. 모델 결과가 도착하는 동안 입력한 수동 초안은 React 컴포넌트의 리비전 변경으로 사라지지 않으며, 사용자가 저장을 선택하면 새 모델 번역을 수정 이력에 남깁니다. 중단 후 재개는 남은 구간을, 취소는 작업 상태만 제거합니다.

## 문서·평가·파일

문서는 DRAFT / IN_REVIEW / FINALIZED 상태를 사용합니다. 문단은 원문, 최초 번역문, 현재 번역문, 리비전, 확인 상태, 최근 30개 수정 이력을 보유합니다. 번역 수정·이력 복원·수정안 적용은 새 리비전을 만들고 확인 상태를 해제합니다. 완료에는 비어 있지 않은 번역문, 전 문단 확인, 미처리 이슈 0개가 필요합니다. 후보 A/B 순서는 생성 시 한 번 저장하며 제출에는 6개 유효 점수와 선호도가 필요합니다.

파일은 UTF-8을 확인하고 CSV 셀 내부 쉼표·줄바꿈·따옴표를 처리합니다. SRT·VTT 시간·구간 식별자·줄바꿈을 보존합니다. CSV 내보내기는 수식 시작 문자를 이스케이프합니다. JSON 백업은 `format: ian-review-workspace`, `version: 1`, `exportedAt`, `data` 구조입니다. 중복 ID·잘못된 타입·날짜·참조·상한 초과를 거절합니다. 백업과 브라우저 데이터는 암호화되지 않습니다.

## 빌드와 검증

`npm run build`는 타입 검사와 portable 프런트엔드 번들, 정적 호스팅 패키지를 만듭니다. `npm --prefix frontend run build:vite`도 지원합니다. portable 번들러는 이 앱의 고정된 React/Router 의존성을 대상으로 하므로 새로운 동적 모듈 경로를 추가할 때 빌드 검증이 필요합니다. 예제·검증 HTML 보고서는 로컬 Pretendard를 사용합니다. 현재 테스트 범위와 실제 Ollama 미검증 여부는 [TEST_REPORT.md](TEST_REPORT.md)에 기록합니다.
