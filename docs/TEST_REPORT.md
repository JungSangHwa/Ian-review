## 수정한 불일치

- 모델 설정 화면에 섞여 있던 용어집 생성·검토 작업을 프로젝트 용어집 화면으로 옮겼습니다.
- 모델 검증 후 다시 사람이 승인하는 버튼과 임시 기준 안내를 제거했습니다. 새 용어는 자동 저장하고, 기존 기준과 충돌한 표기는 프로젝트 안에서 통일하며 결정 기록을 남깁니다.
- 이전 백업의 초안·승인 대기 용어는 원문 맥락을 포함한 모델 검증으로 결정합니다. 결정 누락·저장 실패·중단 시 준비 완료로 표시하지 않습니다.
- 번역과 재검증 모두 같은 기준 문서를 전달합니다. 검증 모델이 새 용어 번역을 교정하면 초벌 번역에 남은 다른 표기도 통일합니다.
- 번역 화면의 중복 내보내기를 정리하고, 완료 후 장황한 준비 안내를 접어 결과를 볼 공간을 확보했습니다. 기준 문서는 Markdown으로 내려받을 수 있습니다.
- 모바일 용어집 표는 세로 배치로 바꿔 기준 번역·결정 근거·편집을 가로 스크롤 없이 읽을 수 있게 했습니다.
- 서술체 지시를 번역·재검증의 시스템 지시에 함께 적용해 재검증에서 ~다 지문을 높임말로 바꾸는 문제를 보완했습니다.
- 사이드바는 현재 실행 작업을 우선 표시하고 용어집의 묶음 수와 번역의 구간 수를 구분합니다. Windows 단축키 표기를 Ctrl로 맞췄습니다.
- 모델이 한 용어에 여러 원문 근거를 반환하는 경우 모든 근거의 문서·구간·인용 일치를 검사합니다. 확인되지 않은 근거가 하나라도 있으면 저장하지 않습니다.
- 로컬 Ollama 요청의 temperature를 0으로 설정해 용어 선택과 구조화 응답의 무작위성을 줄였습니다. [Ollama 공식 구조화 출력 안내](https://docs.ollama.com/capabilities/structured-outputs)를 기준으로 적용했고 실제 API 요청을 회귀 테스트합니다.
- 용어집·번역·이전 용어 검증에 작업별 JSON Schema를 전달해 필수 필드·구간 ID·응답 개수를 제한합니다. 번역에서 반복된 기존 용어 후보는 저장된 기준을 재사용하며 모델이 되풀이한 메모와 이전 장면 근거를 다시 저장하지 않습니다.
- 중복 구간·잘못된 JSON 등 유효하지 않은 번역 응답은 저장하지 않고 모델에 최대 2회 수정 요청합니다. 계속 실패하면 기존 번역과 저장 완료 수를 유지하고 오류를 표시합니다.
- 모델 재검증 결과에 미처리 규칙 이슈가 없으면 구간 확인을 자동 완료합니다. 규칙 위반은 화면에 유지합니다.

## 검증하지 않은 영역

Windows 배치 실행과 macOS 런처는 제공하지만 이 운영체제에서 직접 실행하지 않았습니다. Safari/Firefox/Edge와 실제 iOS/Android 기기는 별도로 검사하지 않았습니다. 모바일 테스트는 Chromium의 viewport 변경이며 스마트폰 접속·기기 실험이 아닙니다.

일반 Vite `dev` 및 `build:vite`, 새 네트워크 환경에서의 `npm ci`, GitHub 원격 CI 실행, 의존성 최신 취약점 감사는 검증하지 않았습니다. 제작 환경의 네트워크 제약과 업로드된 Windows 네이티브 의존성 때문에 기본 portable 빌드를 사용했습니다. 배포 ZIP은 이 빌드 결과를 포함해 일반 사용 시 npm 설치를 요구하지 않습니다.

장기간 운영, 브라우저 강제 종료/OS 장애 중 복구, 8 MiB 상한의 전체 부하, 여러 사용자·기기 동기화, 완전한 접근성 감사, 외부 전문 보안 감사는 수행하지 않았습니다. 앱은 로컬 개인용이며 팀 운영용 보안·인증·서버 백업을 제공한다고 주장하지 않습니다.

## 재실행

```sh
cd frontend
npm ci
npm run lint
npm test
npm run build
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/e2e.py
```

CI 정의는 `.github/workflows/frontend-ci.yml`에 있습니다. 실제 실행 로그와 테스트 코드를 함께 제공하므로 수정 후 동일한 회귀 검사를 반복할 수 있습니다.
