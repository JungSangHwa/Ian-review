# Ian Review Studio 수정 필요 사항

점검일: 2026-09-27  
대상: 현재 소스와 `http://127.0.0.1:4173`의 로컬 빌드  
상태: 2026-09-27 수정 전 점검 기록. F-01~F-15와 S-01~S-08의 구현은 2026-09-28 수정본에 반영했다. 현재 결과와 남은 검증 범위는 [검증 보고서](TEST_REPORT.md)를 참고한다. 아래의 재현 표와 “현재 상태” 설명은 점검 당시 기록이다.

추가 요구사항: **9절에 사이드바 활용 확대 계획**을 정리했다. S-01~S-08은 추가 설계 항목이며, 앞의 F-01~F-15 결함 점검과 구분한다.

## 1. 유지할 요구사항과 점검 범위

현재 제품 방향은 **로그인 없는 로컬 모델 번역 작업실**이다. 프로젝트별로 문서·용어집·모델 설정·평가를 관리하고, 모델이 만든 용어집을 검증한 다음 번역 전반에 적용해야 한다. 화면은 현재 디자인 방향과 Pretendard를 유지한다.

이미 구현된 프로젝트 생성·이름 변경·삭제, 프로젝트별 페이지, 모델 용어 추출·재검증, 번역 결과 재검증, 앱 본문의 로컬 Pretendard 로딩을 미구현 기능으로 다시 분류하지 않았다. 로그인 화면이나 계정 기능을 추가하는 작업도 범위에 넣지 않았다.

이번 점검에서는 소스 검토, 로컬 HTTP 요청, 메모리 안에서 실행한 도메인 함수 재현, 기존 자동 테스트 재실행을 수행했다. 실제 사용자의 IndexedDB를 변경하지 않았다.

| 확인 항목 | 결과와 해석 |
|---|---|
| 기존 자동 테스트 | **145개 통과, 실패 0개**. 현재 테스트가 다루는 범위의 결과다. |
| 로컬 앱 진입 | `/`와 예제 HTML 페이지는 HTTP 200 |
| 예제 CSV·SRT 다운로드 | 실제 파일이 있으나 HTTP 404 재현 |
| 점이 포함된 프로젝트 홈 주소 | `/projects/QA.v1`에서 HTTP 404 재현 |
| 외부 제공사 모델 목록 요청 | 로컬 서버에서 HTTP 400 재현 |
| 프로젝트·용어집 상태 처리 | 아래 F-02, F-03, F-06, F-07의 도메인 함수 재현 수행 |
| 실제 로컬 모델 추론 | 이번 점검 환경에서 `127.0.0.1:11434/api/tags` 연결 실패. 추론 품질·속도는 검증하지 않았다. 사용자 OS의 설치 여부를 뜻하지는 않는다. |
| 현재 UI의 브라우저 전체 회귀 테스트 | 이번 점검에서 실행하지 않았다. 저장된 테스트 코드가 현재 UI와 맞지 않는 부분은 F-10에 기록했다. |

근거의 **재현**은 HTTP 또는 도메인 함수를 실행해 결과를 확인한 항목이다. **코드 확인**은 관련 구현 경로를 확인했으며, 명시한 브라우저 시나리오는 수정 과정에서 재검증해야 하는 항목이다. 파일의 행 번호는 점검 시점 기준이다.

## 3. P1 상세 작업

### F-01. 로컬 모델 전용 화면과 서버 기능 일치

**문제:** 로컬 모델 설정 화면에서도 OpenAI·Gemini 등 외부 제공사를 선택하고 키를 입력할 수 있다. 하지만 로컬 서버는 `provider !== 'local'` 요청을 거절한다. 선택 가능한 기능과 실제 지원 기능이 다르다.

**재현:** 로컬 `/api/models`에 `provider: "openai"`로 요청하면 HTTP 400과 `로컬 Ollama 모델을 선택해 주세요.`를 반환한다. 실제 외부 API나 키는 사용하지 않았다.

**근거:** [ModelsPage.tsx](../frontend/src/pages/ModelsPage.tsx) 34행의 제공사 목록, [local-model.mjs](../local-model.mjs) 70행의 제공사 검사, [SettingsPage.tsx](../frontend/src/pages/SettingsPage.tsx) 25행의 외부 API 선택 안내.

**수정 방향:** 현재 요구사항에 맞춰 로컬 실행판은 Ollama 모델 선택·연결·번역 흐름으로 정리한다. 외부 제공사 선택과 키 입력을 노출하지 않으며, 이전 백업에 외부 모델 설정이 있으면 로컬 모델을 다시 선택하도록 안내한다. 이전 자료를 읽는 호환성은 보존한다.

**완료 기준:** 로컬 UI에 실행할 수 없는 제공사 선택지가 없고, 모델 목록 조회 → 연결 확인 → 설정 저장 → 번역이 같은 로컬 모델로 이어진다.

### F-02. 용어집 생성 완료 상태와 중단·재개 관리

**문제:** 자동 번역 전 용어집 준비 여부를 “이 프로젝트에 용어가 하나라도 있는가”로 판단한다. 생성이 중간에 멈추거나 수동 용어 하나만 등록돼 있어도 전체 원문 용어집 준비가 끝난 것으로 취급된다. 생성 후 원고를 추가한 경우도 자동 준비 조건에 반영되지 않는다.

**재현:** 원문 2묶음 중 첫 묶음의 추출·검증을 저장하고 중단했다. 진행은 `1/2`, 저장된 용어는 1개인데 다음 자동 준비 조건은 `false`였다. 이 재현은 모델 응답 대역을 사용했다.

**근거:** [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx) 25행, [projectGlossary.ts](../frontend/src/lib/projectGlossary.ts) 80행부터의 묶음별 처리, [model.ts](../frontend/src/lib/model.ts) 19행의 Workspace 구조.

**수정 방향:** 프로젝트별 용어집 생성 작업에 상태, 처리한 원문 범위, 마지막 완료 시점 또는 원문 지문을 저장한다. 부분 완료는 남은 원문부터 재개하고, 신규·변경 원문은 재검증 대상으로 표시한다. 사람의 최종 승인 상태와 모델의 생성·검증 완료 상태는 별도로 관리한다.

**완료 기준:** 부분 생성·새 원고 추가·수동 용어만 있는 경우를 각각 구별한다. 사용자가 정한 전체 용어집 생성·검증 절차가 끝나기 전에 번역 준비 완료로 표시하지 않는다.

### F-03. 공통 용어의 충돌 제안·승인 범위 분리

**문제:** 프로젝트 용어집 생성에서 충돌 제안 중복을 검사할 때 프로젝트가 조건에 없다. 공통 용어에 대해 두 작품이 같은 변경안을 만들면 두 번째 작품의 제안이 누락된다. 또한 한 작품의 모델 설정 화면에서 변경안을 승인하면 공통 용어 자체가 바뀌어 다른 작품에도 영향을 준다.

**재현:** 공통 용어 `Mira → 미라`를 사용하는 Alpha와 Beta에서 `미라나`를 제안했다. Alpha에는 제안 1개가 생겼지만 Beta는 0개였다. Alpha의 제안을 승인하자 Beta에 적용되는 공통 기준도 `미라나`가 됐다.

**근거:** [projectGlossary.ts](../frontend/src/lib/projectGlossary.ts) 65행의 중복 검사, [aiTranslation.ts](../frontend/src/lib/aiTranslation.ts) 27행의 `resolveAITermSuggestion`.

**수정 방향:** 제안의 중복 판정에 프로젝트를 포함한다. 프로젝트 화면에서 공통 용어의 다른 번역을 승인할 때는 해당 작품의 전용 기준으로 추가하는 것을 기본 동작으로 삼는다. 공통 기준 변경은 영향을 받는 작품을 보여 주는 별도 동작으로 구분한다.

**완료 기준:** Alpha의 용어 결정이 Beta의 기준을 조용히 바꾸지 않는다. 두 작품 모두 자기 충돌 제안을 확인·처리할 수 있다.

### F-04. AI 번역 중 미저장 번역문 보호

**문제:** 모델 응답을 기다리는 동안 번역문 편집이 가능하다. 이후 AI 결과가 저장돼 문단 리비전이 바뀌면 편집기의 React `key`도 바뀌어 입력 상태가 새로 생성된다. 이 경로에서 저장하지 않은 수동 번역문을 잃을 수 있다. 수동 입력으로 `dirty` 상태가 되면 일시 중지 버튼도 비활성화된다.

**확인할 시나리오:** 모델 응답을 지연시킨 상태에서 번역을 시작하고 같은 문단에 수동 입력을 한 뒤 모델 응답을 완료한다. 초안 보존과 일시 중지 가능 여부를 확인한다. 이번 점검에서는 이 브라우저 시나리오를 실행하지 않았으며 코드 경로를 확인했다.

**근거:** [ReviewPage.tsx](../frontend/src/pages/ReviewPage.tsx) 41행의 `segment.id:segment.revision` 키와 55행의 `SegmentEditor`, [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx) 46행의 중지 버튼 조건, [aiTranslation.ts](../frontend/src/lib/aiTranslation.ts) 139행의 결과 저장.

**수정 방향:** 번역 중인 구간의 수동 편집을 잠그거나, 초안을 서버·모델 결과와 독립적으로 보관하고 적용 충돌을 안내한다. 중지 버튼은 편집 내용 존재 여부와 무관하게 사용할 수 있도록 한다.

**완료 기준:** 응답 도착·일시 중지·실패·재개 어느 경우에도 미저장 입력이 사라지지 않으며, 중지 동작이 입력 상태 때문에 막히지 않는다.

### F-05. 모델 설정 초안의 임의 초기화 방지

**문제:** 모델 설정의 입력값을 초기화하는 effect가 전체 `state`를 의존한다. 같은 페이지에서 AI 용어를 승인하거나 용어 생성 결과가 저장되기만 해도 입력 중인 모델 ID·번역 메모 등이 저장된 값으로 되돌아간다. 페이지 이동에 대한 미저장 경고도 없다.

**재현 절차:** 모델 설정에 저장하지 않은 번역 메모를 입력한 뒤, 아래 AI 용어 검토 영역에서 용어 하나를 승인한다. 입력값이 유지되는지 확인한다.

**근거:** [ModelsPage.tsx](../frontend/src/pages/ModelsPage.tsx) 23행의 effect와 47행의 용어 승인, [UI.tsx](../frontend/src/components/UI.tsx)의 기존 `UnsavedGuard`.

**수정 방향:** 선택한 프로젝트와 그 설정의 변경만 편집기 초기화 기준으로 삼는다. 초안·저장값·dirty 상태를 분리하고 프로젝트 전환과 페이지 이탈 시 보호한다. 이전 연결 확인·모델 목록 요청의 늦은 응답이 새 선택의 결과처럼 표시되지 않도록 요청 대상도 함께 검증한다.

**완료 기준:** 용어 승인·삭제·생성 중간 저장이 모델 설정 초안을 지우지 않는다. 실제 선택을 바꿀 때는 저장 또는 변경 취소를 선택할 수 있다.

### F-06. 문서 등록으로 만든 프로젝트의 영구 등록

**문제:** 새 문서 화면은 문서를 먼저 만든 다음 `projectNames()`로 프로젝트 존재 여부를 검사한다. 이 함수는 방금 만든 문서에서도 작품 이름을 가져오므로 명시적 프로젝트 목록에 추가하는 분기가 실행되지 않는다. 다른 연결 자료가 없을 때 마지막 문서를 지우면 프로젝트도 사라진다.

**재현:** 새 작품 이름으로 문서 등록 로직을 실행한 결과 `state.projects`는 빈 배열이고 화면용 프로젝트 목록에만 작품 이름이 있었다. 마지막 문서를 지우자 그 목록에서도 사라졌다. 홈에서 프로젝트를 먼저 만든 경우와 결과가 다르다.

**근거:** [NewDocumentPage.tsx](../frontend/src/pages/NewDocumentPage.tsx) 57행, [projects.ts](../frontend/src/lib/projects.ts) 4행의 `projectNames`, [DocumentsPage.tsx](../frontend/src/pages/DocumentsPage.tsx) 21행의 문서 삭제.

**수정 방향:** 문서·용어·설정과 별개로 프로젝트 존재를 보장하는 공통 함수를 사용한다. 문서 등록·프로젝트 이동·기존 백업 읽기에서도 같은 규칙을 적용한다.

**완료 기준:** 마지막 문서를 지워도 명시적으로 프로젝트를 삭제하기 전까지 프로젝트가 남는다. 생성 경로에 따라 프로젝트의 생존 여부가 달라지지 않는다.

### F-07. 취소 요청 전달과 중단된 작업 상태 복구

**문제 A:** 브라우저의 취소 신호는 앱 서버로 가는 요청을 중단하지만, 로컬 서버의 Ollama 호출은 별도 타임아웃 신호만 사용한다. 사용자 중지·연결 종료가 상위 모델 호출 취소로 전달되지 않는다.

**문제 B:** 강제 종료 등으로 저장된 `aiRun.status`가 `running`에 남으면 프로젝트 이름 변경·삭제가 차단된다. 앱을 다시 열 때 실제 실행 주체가 남아 있는지 판정하거나 중단된 작업을 명시적으로 취소하는 경로가 부족하다.

**재현:** `running` 작업이 저장된 상태를 직렬화·재검증한 후 이름 변경을 실행하면 여전히 “진행 중인 모델 번역을 일시 중지”하라는 오류로 차단됐다. 실제 브라우저 강제 종료는 이번에 실행하지 않았다.

**근거:** [local-model.mjs](../local-model.mjs) 23행의 `ollama`와 59행의 요청 처리, [database.ts](../frontend/src/lib/database.ts) 29행의 초기화, [projects.ts](../frontend/src/lib/projects.ts)의 이름 변경·삭제 실행 중 검사.

**수정 방향:** HTTP 연결 종료와 사용자 취소를 Ollama 호출에 연결한다. 저장된 작업에 실행 세션·소유 상태를 확인할 수 있는 정보를 두고, 살아 있는 다른 탭 작업을 건드리지 않으면서 오래된 실행 상태를 복구한다. 재개와 작업 취소를 별도로 제공한다.

**완료 기준:** 중지 후 불필요한 모델 요청이 계속 유지되지 않는다. 비정상 종료 후 재개·취소·프로젝트 관리가 가능하고, 다른 탭에서 실제 실행 중인 작업은 보호된다.

## 4. P2 상세 작업

### F-08. 프로젝트 이름에 따른 새로고침 404 방지

**문제·재현:** 일반 이름 주소 `/projects/QA%20Alpha`는 HTTP 200이지만 `/projects/QA.v1`은 404다. 프로젝트 생성은 점을 허용하는데 로컬 서버가 마지막 경로의 점을 파일 확장자로 해석한다. 프로젝트 내부 이동은 되더라도 홈 주소를 새로고침하거나 직접 열 때 실패할 수 있다.

**근거:** [start.mjs](../start.mjs) 31행의 `path.extname(pathname)` 검사, [projects.ts](../frontend/src/lib/projects.ts)의 이름 검증과 `projectPath`.

**수정 방향·완료 기준:** 앱 라우트와 정적 파일을 구분해 SPA 진입을 처리한다. `작품.v1`, 한글, 공백을 포함한 이름의 프로젝트 홈·문서·용어집을 직접 열고 새로고침할 수 있어야 한다. 소스 파일 노출과 경로 탈출 차단은 유지한다.

### F-09. 예제 CSV·SRT 파일 다운로드 복구

**문제·재현:** `/examples/novel-before.csv`, `/examples/subtitle-source.srt`, `/validation/errors.csv`가 모두 404다. 예제 보고서는 이 파일들을 다운로드 링크로 제공하며 파일도 빌드에 존재한다.

**근거:** [start.mjs](../start.mjs) 15행의 MIME 목록에 CSV·SRT·VTT가 없고, 35행에서 알 수 없는 형식을 404로 처리한다. [예제 보고서](../frontend/public/examples/report.html)에서 해당 파일을 연결한다.

**수정 방향·완료 기준:** 필요한 정적 파일 형식의 응답 타입을 추가하고, 로컬 서버와 배포 서버의 지원 목록을 맞춘다. 보고서의 모든 다운로드 링크를 확인하고 파일 내용·한글 인코딩·자막 시간을 검증한다. 이 문제는 브라우저에서 직접 만드는 TXT·CSV 내보내기와는 별도다.

### F-10. 현재 UI에 맞는 브라우저 테스트 복구

**문제:** 저장된 E2E 테스트는 초기 제목 `번역에 확신을 더하세요.`, `예제로 둘러보기` 버튼, `문서 제목` 필드, `저장하고 검수 시작` 버튼을 찾는다. 현재 화면의 제목·버튼·프로젝트 등록 흐름과 다르다. 자동 테스트 145개 통과만으로 현재 UI 전체를 검증했다고 볼 수 없다.

**근거:** [e2e.py](../frontend/tests/e2e.py) 66행·75행·90행, [frontend-ci.yml](../.github/workflows/frontend-ci.yml)의 브라우저 테스트 실행 단계.

**수정 방향·완료 기준:** 현재 프로젝트 흐름으로 공통 생성 도우미와 화면 선택자를 갱신한다. 최소한 프로젝트 생성·전환·이름 변경·삭제, 프로젝트별 문서·용어 분리, 모델 설정 초안 보호, 생성 중단·재개, 다운로드, 모바일 메뉴를 검사한다. CI에서 현재 빌드를 대상으로 전체 브라우저 테스트가 통과해야 한다. 대역 모델을 쓰는 UI 테스트와 실제 Ollama 검증 결과는 구분해 기록한다.

### F-11. 용어집에서 실제 적용 기준·충돌 제안 확인

**문제:** 프로젝트 용어집 화면은 그 프로젝트에 직접 속한 용어만 보여 주지만 실제 번역은 공통 용어도 적용한다. 기존 기준과 충돌하는 AI 제안은 모델 설정 페이지에서만 검토할 수 있다. 번역 패널은 용어집에서 새 용어와 충돌 제안을 확인할 수 있다고 안내한다.

**근거:** [GlossaryPage.tsx](../frontend/src/pages/GlossaryPage.tsx) 18행·23행, [ModelsPage.tsx](../frontend/src/pages/ModelsPage.tsx) 45행부터의 AI 용어 검토, [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx)의 용어집 안내.

**수정 방향·완료 기준:** 용어집에 프로젝트 기준·상속된 공통 기준·검토 대기·충돌 제안을 구분해 표시한다. 원문 근거와 승인·유지·삭제 동작을 연결하고 공통 용어 변경 범위를 드러낸다. 번역에 실제 쓰이는 기준을 사용자가 한곳에서 확인할 수 있어야 한다.

### F-12. 등록 가능한 문서와 번역 가능한 문서의 제한 정리

**문제:** 문서는 최대 500구간, 문단당 20,000자로 등록할 수 있다. 그런데 자동 번역은 12,000자를 넘는 문단을 처리하지 못하며, 전체 재번역은 100구간 초과 시 UI에서 막힌다. 등록을 마친 뒤에야 번역할 수 없다는 사실을 알게 된다.

**근거:** [model.ts](../frontend/src/lib/model.ts) 26행의 제한, [aiTranslation.ts](../frontend/src/lib/aiTranslation.ts) 67행, [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx) 22행.

**수정 방향·완료 기준:** 등록 단계에서 번역 가능 여부를 확인하고 긴 문단의 분할·대안 처리를 안내한다. 이미 존재하는 묶음 번역 방식과 전체 재번역 제한을 일관되게 정리한다. 문단 분할 시 원문 순서와 자막 구간·시간이 보존돼야 한다. 긴 문서에서 나중에 실패하는 경우를 미리 알려야 한다.

### F-13. 모바일 프로젝트 전환 후 메뉴 닫기

**문제:** 모바일 사이드바의 프로젝트 선택창은 이동만 실행한다. 일반 메뉴 링크는 메뉴를 닫지만 선택창의 `onChange`는 `menuOpen`을 갱신하지 않아 새 프로젝트 위에 사이드바가 남는다.

**근거:** [AppLayout.tsx](../frontend/src/components/layout/AppLayout.tsx) 29행의 프로젝트 선택과 31행의 일반 메뉴 처리.

**수정 방향·완료 기준:** 선택이 확정되어 프로젝트 이동이 완료되면 모바일 메뉴를 닫고 새 화면으로 초점을 돌린다. 미저장 경고로 이동이 취소된 경우 선택 표시도 현재 프로젝트와 일치해야 한다. 기존 선택창의 `width: 100%`, 하단 여백 13px, Pretendard는 유지한다.

### F-14. 상태 배지 색상·보고서 폰트 및 CSS 정리

**문제 A:** CSS 마지막 테마의 `.badge`가 앞서 선언된 `.badge--green`, `.badge--orange`, `.badge--red`와 같은 선택자 우선순위로 배경·글자색을 덮는다. 상태별 배지가 공통 보라색으로 표시될 수 있다.

**문제 B:** 앱 본문은 Pretendard를 사용하지만 별도 예제·검증 HTML 보고서는 `system-ui`를 사용한다. 스타일시트에는 이전 테마와 신규 테마가 누적돼 같은 선택자를 여러 번 덮어쓴다.

**근거:** [styles.css](../frontend/src/styles.css)의 앞부분 상태 배지 규칙과 123행 이후 신규 테마, [export-literary.cjs](../frontend/scripts/export-literary.cjs) 61행, [export-test-set.cjs](../frontend/scripts/export-test-set.cjs) 67행의 보고서 템플릿.

**수정 방향·완료 기준:** 배지의 공통 형태와 상태별 색상을 분리하고 기본 테마·반응형 규칙을 정리한다. 보고서 생성 템플릿에도 로컬 Pretendard를 적용한다. 성공·경고·오류가 색과 텍스트로 구분되고, 데스크톱·390px 모바일·인쇄 및 생성 보고서에서 의도한 폰트가 적용돼야 한다.

| 위 문서가 마지막 문서일 때 삭제 | 파생 프로젝트 목록도 빈 배열로 변경 |

| Alpha·Beta의 같은 공통 용어 변경 제안 | Alpha 충돌 1건, Beta 충돌 0건 |
| Alpha에서 위 변경 제안 승인 | Beta에도 적용되는 공통 기준 변경 |
| 저장된 `running` 작업 읽기 후 프로젝트 이름 변경 | 일시 중지를 요구하는 오류로 차단 |

도메인 재현은 실제 저장소 대신 새로 만든 메모리 데이터와 모델 응답 대역을 사용했다. 실제 모델의 번역 정확성을 입증하는 결과가 아니다.

## 9. 사이드바 활용 확대 계획

### 목표와 현재 상태

사이드바에서 **프로젝트 선택 → 다음 작업 확인 → 원고·용어 등록 → 진행 중 작업 확인 → 검수 재개**까지 이어지도록 구성한다. 사용자가 현재 작품, 남은 작업, 연결된 로컬 모델을 페이지마다 다시 찾아다니지 않아도 되어야 한다.

현재 [AppLayout.tsx](../frontend/src/components/layout/AppLayout.tsx)에는 프로젝트 선택창, 페이지 메뉴, 문서 수, 백업·도움말 링크가 있다. 최근에 열었던 문서, 작업별 필터 바로가기, 용어 검토 대기 수, 모델 상태와 실행 중 작업을 다루는 영역은 없다. 프로젝트 선택창과 현재 프로젝트 카드의 중복은 줄이고 실제 작업에 필요한 정보에 공간을 배정한다.

기존 Pretendard와 밝은 배경·보라색 강조를 유지한다. 로그인·프로필 영역은 추가하지 않는다. 숫자·진행률·연결 상태는 실제 데이터에서 가져오고, 클릭할 대상이나 동작이 구현된 항목만 노출한다.

### S-01. 프로젝트 선택 강화

- 프로젝트 선택 영역에 이름 검색을 제공하고 현재 프로젝트, 고정 프로젝트, 최근 사용 프로젝트를 쉽게 찾게 한다. 초기 표시 상한은 고정 3개·최근 5개로 두고 전체 목록으로 확장할 수 있게 한다.
- 현재 선택창을 유지하는 1차 구현에서는 `width: 100%`, 하단 여백 13px, 글자 크기 12px를 유지한다. 검색 가능한 선택기로 확장할 때도 같은 정렬·여백을 기준으로 삼는다.
- 선택창 옆 `+`는 이름 입력 다이얼로그를 열고 기존 `createProject`로 실제 저장한다. 저장 성공 후 생성한 프로젝트로 이동하고 저장 실패 시 입력을 보존한다.
- 프로젝트 전환 시 원고·자막, 용어집, 모델 설정, 평가 목록 같은 공통 화면은 새 프로젝트의 같은 화면으로 이동한다. 개별 문서·평가 상세에서 전환하면 새 프로젝트의 해당 목록으로 이동한다. 이전 프로젝트의 문서 ID를 새 주소에 붙이지 않는다.
- 데이터 관리·도움말 등 전체 작업 공간 화면에는 `전체 작업 공간`이라는 범위를 표시한다. 마지막 선택 프로젝트는 다시 열기용으로 보관하되 현재 화면의 작업 범위를 잘못 나타내지 않는다.
- 고정·최근 목록은 이 브라우저의 UI 설정으로 보관한다. 이름 변경 시 표시와 참조를 갱신하고 삭제된 프로젝트는 목록에서 제거한다. 고정 프로젝트 ID 도입 전에는 이 동작을 공통 이름 변경·삭제 처리와 함께 구현한다.

**완료 기준:** 검색·생성·전환이 모두 실제 프로젝트에 연결된다. 이동을 취소하면 선택 표시도 원래 프로젝트로 돌아오며, 새로고침 후에도 고정·최근 목록이 유지된다.

### S-02. 등록 바로가기

기본 버튼은 `원고·자막 추가`와 `용어 추가` 두 개로 제한한다. 자막 등록은 원고·자막 추가의 보조 메뉴로 제공한다.

| 동작 | 목적지 또는 처리 | 현재 지원 상태 |
|---|---|---|
| 원고 추가 | `projectPath(project, 'documents/new')` | 현재 경로 재사용 가능 |
| 자막 추가 | 위 주소에 `?type=subtitle` | 현재 쿼리 처리 재사용 가능 |
| 용어 추가 | 선택 프로젝트 용어집에서 새 용어 폼 열기 | 사이드바에서 폼을 여는 연결 추가 필요 |
| 새 프로젝트 | 프로젝트 생성 다이얼로그 → 저장 → 프로젝트 홈 | 기존 생성 함수 재사용, 사이드바 진입점 추가 필요 |

용어 추가에는 예를 들어 `?action=new` 진입 처리를 추가하되, 현재 이미 지원되는 경로처럼 취급하지 않는다. 폼의 적용 작품은 현재 프로젝트로 고정한다. 폼 닫기·새로고침 시 의도치 않게 반복해서 열리지 않도록 진입 상태를 처리한다.

프로젝트가 선택되지 않은 상태에서 프로젝트 전용 등록 버튼을 누르면 먼저 작품을 선택하거나 생성하게 한다. 첫 번째 프로젝트를 임의로 골라 저장하지 않는다. 현재 페이지에 미저장 입력이 있으면 등록 화면으로 이동하기 전에 보존·이동 취소 절차를 거친다.

**완료 기준:** 사이드바로 등록한 문서·용어가 선택한 프로젝트에만 저장된다. 현재 선택과 실제 저장 위치가 어긋나는 경우가 없다.

### S-03. 작업 현황과 필터 이동

사이드바 숫자는 아래처럼 의미와 단위를 고정한다. 문서 수, 문단 수, 이슈 수를 같은 의미의 숫자처럼 섞지 않는다.

| 표시 | 계산 기준 | 클릭 동작 |
|---|---|---|
| 원고·자막 `n개` | 현재 프로젝트 문서 수 | 프로젝트 문서 목록 |
| 검수 중 `n개` | 상태가 `IN_REVIEW`인 현재 프로젝트 문서 수 | 문서 목록 `?status=IN_REVIEW` |
| 미처리 이슈 문서 `n개` | 열린 이슈가 하나 이상 있는 현재 프로젝트 문서 수 | 문서 목록 `?issues=1` |
| 작품 용어집 `n개` | 해당 작품에 직접 속한 용어 수 | 프로젝트 용어집. 상속된 공통 용어는 별도로 표시 |
| 용어 검토 대기 `n건` | 작품의 draft 용어 수 + pending 충돌 제안 수 | 두 종류를 구분해 보여 주는 용어 검토 화면 |
| A/B 평가 `n개` | 해당 프로젝트에 속한 평가 수 | 프로젝트 평가 목록 |

문서 상태·이슈 필터는 [DocumentsPage.tsx](../frontend/src/pages/DocumentsPage.tsx)의 현재 쿼리 처리를 재사용한다. 용어 검토 대기는 F-11의 화면을 구현한 뒤 연결한다. 서로 다른 언어 쌍의 용어가 있으면 검토 화면에서 구분하고, 프로젝트의 전체 대기 건수와 필터 적용 후 건수를 명확히 보여 준다.

공통 용어는 실제 번역에 적용되지만 작품 전용 용어 개수에 합산하지 않는다. 0건을 오류 상태로 표시하지 않는다. 다른 탭의 변경으로 현재 데이터가 오래되었다면 숫자를 최신 상태라고 단정하지 않고 기존 갱신 안내와 연결한다.

**완료 기준:** 각 숫자를 클릭한 결과의 대상·개수가 사이드바 설명과 일치한다. 저장·승인·삭제 이후 숫자가 함께 갱신되고 다른 작품의 자료가 섞이지 않는다.

### S-04. 최근 문서와 이어서 검수

- 프로젝트별로 최근 **열었던** 문서 3개와 마지막 선택 문단을 기록한다. `updatedAt` 순서는 최근 수정 순서이므로 최근 열기 기록을 대신하지 않는다.
- `이어서 검수`는 프로젝트 소속과 문서 존재 여부를 확인한 뒤 `review/:id?segment=:segmentId`로 이동한다. 문단이 없어졌으면 첫 유효 문단으로, 문서가 삭제됐으면 프로젝트 문서 목록으로 안내한다.
- 제목은 두 줄 이내로 줄이되 전체 이름을 확인할 수 있게 한다. 제목과 함께 검수 상태를 텍스트로 표시한다.
- 최근 기록·접기 상태·고정 목록은 문서의 수정 시각이나 리비전을 변경하지 않는 UI 설정으로 저장한다. 전체 작업 데이터 백업에는 넣지 않는 것을 기본으로 하며, 데이터 복원 후에는 존재하는 프로젝트·문서만 다시 연결한다.

**완료 기준:** 두 프로젝트를 번갈아 열어도 각각의 마지막 문서·문단을 복원한다. 문서 삭제·프로젝트 이름 변경·백업 복원 후 잘못된 상세 주소로 이동하지 않는다.

### S-05. 번역·용어집 작업 제어

이 항목은 페이지 이동 중에도 작업을 계속 실행할 수 있도록 구조를 바꾼 뒤 제공한다. 현재 [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx)와 [ModelsPage.tsx](../frontend/src/pages/ModelsPage.tsx)는 페이지 안에서 실행 상태와 취소 컨트롤러를 소유하며, 해당 컴포넌트가 사라지면 요청을 취소한다. `aiRun`의 저장 상태만 읽어 사이드바에 “백그라운드 실행 중”이라고 표시해서는 안 된다.

**필요한 선행 구현:** 페이지 밖의 공통 작업 관리 계층에서 실행 작업·취소 신호·단계·오류를 관리한다. 문서 및 프로젝트 작업의 실행 주체를 확인하고, 동일 작업을 중복 실행하지 못하게 한다. 첫 구현은 로컬 모델 동시 실행 1개를 기본으로 삼으며 추가 실행 요청은 기존 작업으로 안내한다. 자동 작업 대기열은 별도 기능이 구현되기 전까지 노출하지 않는다.

| 상태 | 사이드바 표시와 동작 |
|---|---|
| 용어 후보 추출 | 작품 이름, 현재 묶음, `용어 후보 추출 중` |
| 용어 모델 검증 | `용어 검증 중`, 저장 완료 묶음 / 전체 묶음 |
| 번역 생성·검증 | 문서명, 실제 단계, 저장 완료 구간 / 전체 구간 |
| 일시 중지 요청 | `중지 중` 표시, 중지 완료 확인 전 재개 버튼 노출 금지 |
| 일시 중지·실패 | 저장된 범위, 간단한 사유, `작업 열기`·`재개` 또는 모델 설정 바로가기 |
| 완료 | 저장 완료 결과와 `검수 열기` |

검증 응답만 받았거나 저장에 실패한 구간을 완료 수에 포함하지 않는다. 추출 단계의 50%와 번역 단계의 50%를 근거 없이 합쳐 전체 진행률처럼 표시하지 않는다. 중지·재개는 화면의 선택 프로젝트가 아니라 카드에 명시된 작업 ID를 대상으로 실행한다.

프로젝트를 전환해도 실행 중인 작업 카드는 대상 작품을 계속 명시한다. 페이지 간 이동은 작업을 유지하도록 구현하지만, 브라우저 탭 종료 후 서버에서 계속 실행되는 기능까지 약속하지 않는다. 탭 재실행 후에는 F-07의 복구 판정을 거쳐 남은 작업을 재개한다.

**완료 기준:** 작업 중 페이지·프로젝트를 이동해도 같은 실행 상태를 확인할 수 있다. 중복 실행, 다른 작품 작업의 오작동, 미저장 입력 손실이 없고 중지·재개가 실제 모델 요청과 저장 결과에 연결된다.

### S-06. 로컬 모델 상태

현재 프로젝트에 저장된 모델 이름과 실제 연결 확인 결과를 구분한다. 모델 설정이 저장돼 있다는 이유만으로 “연결됨”을 표시하지 않는다.

| 표시 | 의미와 다음 동작 |
|---|---|
| 모델 미설정 | 작품 모델 설정으로 이동 |
| 설정됨 · 연결 미확인 | 모델 이름 표시, 사용자가 `연결 확인` 실행 가능 |
| 확인 중 | 중복 확인 요청 방지, 현재 선택 모델 명시 |
| 마지막 연결 확인 성공 · 시각 | 해당 모델로 테스트가 성공한 기록. 현재도 항상 사용 가능하다는 의미는 아님 |
| 연결 실패 | 설치·실행 상태 또는 선택 모델을 확인하도록 설정 화면 연결 |

연결 확인은 사용자 동작으로 실행한다. 화면 전환이나 사이드바 렌더링마다 추론 요청을 자동으로 보내지 않는다. 모델 변경 시 이전 확인 결과를 무효화하며, 늦게 도착한 응답을 다른 프로젝트나 모델의 성공 결과로 표시하지 않는다. 로컬 실행 중인 작업과 연결 확인 요청이 경쟁하지 않도록 공통 실행 정책을 적용한다.

**완료 기준:** 표시한 모델·작품·확인 결과가 실제 요청 대상과 일치하고, 설정만 저장한 상태와 검증을 마친 상태를 구분할 수 있다.

### S-07. 접기·모바일·키보드 조작

- 데스크톱은 펼침 약 264px·접힘 약 72px를 초기 설계값으로 검토한다. 본문 검수 편집 영역이 지나치게 좁아지지 않도록 화면 폭에 따라 조정한다.
- 접힌 상태에도 현재 프로젝트와 메뉴 의미를 확인할 수 있는 접근 가능한 이름·툴팁을 제공한다. 프로젝트 선택과 주요 작업을 마우스 올리기만으로 사용할 수 있게 만들지 않는다.
- 상단 프로젝트 선택과 하단 관리 영역 사이를 스크롤 가능한 영역으로 만든다. 높이가 작은 창에서 최근 문서·작업 카드가 메뉴와 백업 버튼을 화면 밖으로 밀어내지 않아야 한다.
- 모바일은 현재 오버레이 형태를 발전시킨다. 폭은 화면보다 작게 제한하고, 메뉴 내부 초점 이동·Escape 닫기·닫은 뒤 초점 복원을 지원한다. 메뉴가 열려 있는 동안 배경 조작과 배경 스크롤을 막는다.
- 메뉴 클릭 또는 프로젝트 전환이 실제 완료됐을 때 닫는다. 미저장 경고에서 이동을 취소한 경우 현재 작품과 편집 상태를 그대로 유지한다.
- 경고·작업 상태는 색만으로 구분하지 않고 문구를 함께 사용한다. 접기 상태와 섹션 펼침 상태는 이 브라우저의 UI 설정에 저장한다.

**완료 기준:** 1440px 데스크톱, 390px 모바일, 높이 600px의 창에서 모든 메뉴에 접근할 수 있다. 키보드만으로 프로젝트 선택·빠른 등록·작업 열기·메뉴 닫기를 수행할 수 있다.

### S-08. 백업과 관리 접근

하단의 반복 설명 카드는 `전체 백업`, `데이터 관리`, `사용 가이드`와 모델 상태를 중심으로 간결하게 정리한다. 전체 백업은 현재 [files.ts](../frontend/src/lib/files.ts)의 `exportBackup`을 연결하고, 클릭 결과가 JSON 다운로드라는 점을 표시한다.

현재 백업은 전체 작업 공간을 포함하므로 사이드바가 특정 작품을 선택한 상태라도 버튼 이름을 `전체 백업`으로 유지한다. 6절의 프로젝트 단위 백업이 실제 구현된 뒤에만 `이 프로젝트 백업`을 별도 동작으로 제공한다. 브라우저의 다운로드 요청 생성과 사용자가 파일을 최종 보관한 사실은 구분한다.

**완료 기준:** 현재 프로젝트 선택에 상관없이 백업 범위가 명확하다. 로그인·사용자 아바타가 재도입되지 않고 관리 링크가 실제 페이지로 이동한다.

### 구현 순서와 확인 시나리오

**1차:** S-01·S-02·S-03·S-08의 실제 경로와 동작을 연결하면서 S-07의 레이아웃을 적용한다. 아직 없는 용어 검토 필터나 새 용어 진입 처리는 버튼과 함께 구현한다.

**2차:** S-04의 최근 사용 기록과 S-06의 모델 상태를 추가한다. 이름 변경·삭제·백업 복원 시 UI 기록을 정리하는 규칙도 함께 적용한다.

**3차:** 작업 실행을 공통 계층으로 옮기고 F-02·F-04·F-07을 해결한 다음 S-05를 활성화한다. 사이드바에 그려진 진행률과 실제 실행 상태가 일치하는지 검증한다.

- [ ] 프로젝트가 없는 상태에서도 사이드바에서 작품을 만들고 첫 문서를 등록할 수 있다.
- [ ] Alpha와 Beta에 서로 다른 문서·용어·평가를 만든 뒤 전환하면 목록·배지·빠른 등록 대상이 함께 바뀐다.
- [ ] 미처리 이슈와 용어 검토 배지를 누르면 표시된 개수에 해당하는 목록이 열린다.
- [ ] 두 작품의 마지막 문서와 문단을 각각 복원하며 삭제한 문서로 이동하지 않는다.
- [ ] 미저장 입력이 있는 상태에서 프로젝트 전환을 취소하면 입력·선택·메뉴 상태가 유지된다.
- [ ] 프로젝트 이름 변경·삭제·작업 공간 복원 후 고정·최근 목록에 잘못된 참조가 남지 않는다.
- [ ] 모델 설정만 저장한 상태를 연결 성공으로 표시하지 않는다.
- [ ] 작업 중 화면을 이동한 뒤에도 카드의 대상 작품·문서·단계·저장 완료 수가 실제 실행과 일치한다.
- [ ] 실패·저장 충돌·중지·재개 시 성공 배지나 완료 진행률을 잘못 표시하지 않는다.
- [ ] 접기·작은 화면·키보드 조작에서도 프로젝트 선택, 등록, 백업에 접근할 수 있다.

주요 수정 대상은 [AppLayout.tsx](../frontend/src/components/layout/AppLayout.tsx), [styles.css](../frontend/src/styles.css), [WorkspaceContext.tsx](../frontend/src/state/WorkspaceContext.tsx)와 프로젝트·문서·용어집 페이지다. 작업 제어는 [AutoTranslationPanel.tsx](../frontend/src/components/AutoTranslationPanel.tsx), [projectGlossary.ts](../frontend/src/lib/projectGlossary.ts), [aiTranslation.ts](../frontend/src/lib/aiTranslation.ts)의 실행 수명 주기 변경을 포함한다. 신규 UI 설정과 작업 상태 필드는 저장·복원 호환성을 함께 설계한다.
