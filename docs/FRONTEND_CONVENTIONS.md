# 프런트엔드 유지보수 원칙

도메인 불변 조건은 페이지의 disabled 버튼에만 의존하지 말고 `lib/actions.ts`, `lib/model.ts`, `lib/validation.ts`에서도 검사합니다. 저장 변경은 `useWorkspace().run`을 통해 단일 IndexedDB 트랜잭션으로 처리합니다. 페이지에서 IndexedDB에 직접 쓰지 않습니다.

사용자가 입력하는 값은 컴포넌트의 로컬 draft에 유지하고 명시적으로 저장합니다. 저장 실패 시 draft를 비우거나 성공 알림을 띄우지 않습니다. 이동 경고에는 `UnsavedGuard`를 사용합니다. 사용자가 원래 데이터를 잃는 삭제·복원 동작에는 확인 UI를 둡니다.

공통 버튼·다이얼로그·배지·로딩/실패 화면은 `components`에, 파일 처리와 도메인 로직은 `lib`에 둡니다. URL에 문서/평가 ID를 사용하고 존재하지 않는 ID에는 복구 가능한 안내 화면을 제공합니다. 사용자 입력을 HTML로 삽입하지 않습니다.

타입·상한·상태를 변경할 때 백업 validator와 round-trip 테스트를 함께 수정합니다. 호환되지 않는 백업 변경에는 schemaVersion 증가와 명시적 마이그레이션이 필요합니다. 기존 데이터를 초기화해서 마이그레이션을 대신하지 않습니다.

규칙 검사 결과를 AI 분석, 의미 품질 인증 또는 실제 사용자가 수행한 검토로 표시하지 않습니다. 예제 데이터는 `isDemo`를 유지합니다. 저장 기능이 없는 UI나 성공하는 척하는 버튼을 추가하지 않습니다.

PR 전에 `npm run lint`, `npm test`, `npm run build`, `python tests/e2e.py`를 실행합니다. 색상·폰트·레이아웃 변경 후 데스크톱과 390px 모바일 폭의 검수 화면도 확인합니다. 수동 확인과 자동 테스트 결과를 구분해 기록합니다.
