# Ian — 웹소설·자막 번역 검수 작업실

Ian은 계정 없이 브라우저에 작업을 저장하는 **로컬 모델 번역 작업실**입니다. 프로젝트별 원고·자막, 용어집, Ollama 모델 설정, A/B 평가를 관리합니다. 모델이 원문 전체의 용어집을 생성·검증한 뒤 기준 문서로 저장합니다. 번역과 재검증은 같은 기준 문서를 사용하며 용어에 대한 사람의 승인은 필요하지 않습니다.

[수정 계획과 완료 기준](docs/PROJECT_FIX_PLAN_KO.md) · [현재 검증 기록](docs/TEST_REPORT.md) · [구조](docs/ARCHITECTURE.md)

## 시작하기

GitHub에서 소스를 내려받았다면 먼저 앱을 빌드합니다.

```sh
git clone https://github.com/JungSangHwa/Ian-review.git
cd Ian-review
npm --prefix frontend ci
npm run build
```

빌드가 끝나면 아래 순서로 실행합니다. 이미 `frontend/dist`가 포함된 실행 패키지는 빌드를 생략할 수 있습니다.

1. [Ollama](https://ollama.com/download)를 설치하고 실행한 뒤 채팅 모델을 내려받습니다. 예: `ollama pull qwen3:8b`.
2. Node.js 22.12.0 이상에서 `node start.mjs`를 실행하고 `http://127.0.0.1:4173`을 엽니다. Windows에서는 `START_WINDOWS.bat`, macOS·Linux에서는 `sh START_MAC_LINUX.sh`를 사용할 수 있습니다.
3. 사이드바나 홈에서 프로젝트를 만들고 원고·자막을 등록합니다. 사이드바의 빠른 등록은 선택한 프로젝트에 저장합니다.
4. 프로젝트의 **모델 연결**에서 설치된 로컬 모델을 불러오고 연결을 확인한 뒤 설정을 저장합니다. API 키는 필요하지 않습니다. 이전 백업의 외부 모델 설정을 읽을 수는 있지만 번역하려면 로컬 모델을 다시 선택해야 합니다.
5. 검수 화면에서 번역을 시작합니다. 원문 전체의 용어집 생성·검증이 끝나지 않았으면 남은 묶음을 먼저 처리합니다. 새 원고나 모델 설정 변경은 다시 검증할 범위에 반영됩니다.
6. 프로젝트 용어집에서 모델이 저장한 기준과 표기 결정 기록을 확인하고, 번역 결과를 TXT·CSV 또는 원래 SRT·VTT 형식으로 내보냅니다. 작업 후 **전체 백업 · JSON**을 내려받습니다.

서버는 `127.0.0.1`에만 바인딩하고, 모델 요청은 같은 PC의 `127.0.0.1:11434` Ollama로 전달합니다. 사용자 문서는 브라우저의 IndexedDB에 저장됩니다. 항상 같은 브라우저·프로필·사이트 주소와 포트를 사용하세요. 앱 폴더만 복사해도 브라우저 데이터는 이전되지 않습니다. 백업과 데이터는 별도 암호화하지 않습니다.

## 작업 흐름

- **프로젝트:** 이름 변경·삭제가 연결된 문서·용어·평가·설정에 반영됩니다. 문서 등록으로 만든 프로젝트도 마지막 문서를 지운 뒤 남습니다. 사이드바의 검색, 최근·고정 목록, 최근 문서, 작업 수치는 이 브라우저의 UI 설정입니다.
- **원고·자막:** UTF-8 TXT·CSV 원고와 SRT·VTT 자막을 등록합니다. 자막 시간·식별자·줄바꿈을 유지합니다. 문서당 최대 500구간, 구간당 최대 20,000자를 등록할 수 있습니다. **12,000자 초과 구간은 모델 자동 번역 대상이 아니며**, 등록 화면에서 이를 안내합니다. 웹소설은 문단을 나눠 등록하거나 수동 번역할 수 있습니다. 자막 시간 구간은 자동 분할하지 않습니다.
- **용어집:** 작품 기준이 공통 기준보다 우선합니다. 모델이 검증한 새 용어는 자동으로 기준 문서에 저장합니다. 애매한 용어는 원문 맥락으로 결정하고, 기존 기준과 다른 표기는 기존 번역에 통일합니다. 공통 용어의 표기 관찰은 프로젝트에만 기록하며 다른 프로젝트의 기준을 변경하지 않습니다. 이전 백업의 초안·충돌 대기도 모델이 검증합니다.
- **번역과 검수:** 모델 생성·검증 결과는 저장된 구간만 완료 수에 포함합니다. 페이지를 옮겨도 진행 중 작업을 사이드바에서 확인하고 일시 중지할 수 있습니다. 재개와 취소를 구분하며 취소해도 이미 저장된 번역은 남습니다. 모델 결과가 도착하는 동안 입력한 수동 초안은 보존되고, 덮어 저장할 때 확인을 받습니다. 모델 재검증을 통과하고 규칙 이슈가 없는 구간은 자동으로 확인 완료됩니다. 회차 간 문체를 위해 이전 문서의 확인된 번역 문맥도 전달합니다. 숫자·변수·용어 검사와 직접 등록한 이슈를 함께 검토하세요.
- **평가와 백업:** 두 번역을 A/B로 비교해 점수와 선호도를 저장합니다. JSON 백업·복원은 전체 작업 공간 단위이며 복원 직전 사본을 한 개 보관합니다. 사이드바의 최근·고정 기록과 연결 확인 기록은 작업 데이터 백업에 들어가지 않습니다.

기본 예제는 웹소설 2회차·자막 8구간(총 20구간)과 작품 용어 8개입니다. 브라우저별로 한 번 추가하며 사용자가 삭제한 예제를 자동으로 다시 넣지 않습니다. [예제 보고서](frontend/public/examples/report.html)는 별도로 작성한 합성 원문·번역에 용어집을 적용한 기록이고 실제 Ollama 품질 평가가 아닙니다.

실제 Ollama로 처리한 창작 소설 3회차는 [안개항의 마지막 종 예제](examples/novel-harbor/README.md)에 원문·최종 교정문·모델 용어집과 함께 보관했습니다. [검증 기록](docs/REAL_NOVEL_TEST_2026-10-04.md)은 자동 생성 결과와 Codex의 추가 교정을 구분합니다.

## 개발과 검증

```sh
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend test
npm run build
python -m pip install -r frontend/tests/requirements.txt
python -m playwright install chromium
python frontend/tests/e2e.py
```

로컬 개발 서버는 `npm run dev`로 실행할 수 있습니다. `npm run build`는 타입 검사와 배포용 번들, 정적 호스팅 패키지를 만듭니다. `frontend/dist`가 포함된 패키지는 일반 사용에 `npm install`이 필요하지 않습니다. 현재 검증 결과는 [TEST_REPORT.md](docs/TEST_REPORT.md)에 기록합니다.

이 앱은 개인 로컬 작업용입니다. 로그인, 클라우드 동기화, 팀 권한, 암호화, DOCX/PDF 직접 파싱은 제공하지 않습니다. 규칙 검사와 모델 재검증은 번역의 의미 정확도를 보증하지 않습니다.
